# 漏洞类型与检测手段调研

> 本文件是 mcpfuzz 判定（oracle）模块重构的基础材料：先讲清每一类注入漏洞的**触发原理、在 MCP 服务里的样子、危害、利用的本质**，再梳理**可行的检测手段**，最后汇成一张「漏洞类型 × 判定原语」矩阵。目标是在知道原理的前提下，讨论出一套**通用、多通道、以差分为骨架、带外可选不必选**的判定方法论。

## 0. 为什么在「危险边界 / 注入类别」这一层做枚举

同一个参数可以从三个层次看待：

| 层次 | 例子 | 是否可枚举 |
|---|---|---|
| ① 后端程序 | git、kubectl、ffmpeg、pandoc、自研脚本…… | ❌ 无穷长尾 |
| ② **危险边界 / 注入类别** | 操作系统 shell、程序 argv 解析、文件系统路径、URL/网络发起、SQL 解析、代码求值 | ✅ **有限封闭** |
| ③ 字段名 | path、url、ref、command…… | ❌ 任意命名 |

注入的本质恒定：**不可信数据流进一个会把它当「结构/指令」而非「纯数据」解释的边界（解释器），缺少正确的分隔/转义，于是数据被解释成结构。** “边界”就是这个解释器的类型——现实中能造成服务端注入的解释器类型就那么几种（对应 CWE 注入家族），是封闭的。

在②这一层枚举的三个作用：
1. **界定完整性**：声称“覆盖注入类漏洞”可辩护——我们覆盖的是这个封闭的边界集合，而不是声称认识所有程序。
2. **让载荷与判定按边界组织，天然覆盖没见过的程序**：无论后端是什么程序，要造成危害，数据最终都汇入这几条边界之一；只要判断出“参数流向哪条边界”，就复用该边界的全套打法，无需先认识这个程序。
3. **它是检测的基本单位**：sink 推断的目标、载荷族划分、判定矩阵的行，都以②为单位。

---

## 通用解剖：一切注入 = 源 → 边界 → 解释器

> 不可信输入（**源**：工具参数值）→ 流入会把它当结构解释的**边界**（解释器）→ 因缺少正确分隔/转义，被解释成**结构/指令**而非纯数据。

下面六类的区别只在于“边界/解释器”是谁。前四类为当前阶段（MVP）支持，后两类为第二阶段。

---

## 1. 命令注入（操作系统 shell 边界）

- **原理**：参数被拼进交给系统 shell（`/bin/sh -c "…"`）执行的命令串。shell 把 `;`、`|`、`` ` ``、`$()`、`&&` 等元字符解释为命令分隔/替换/串联，参数里的这些字符让攻击者命令挤进同一次 shell 执行。若程序用 execFile 直接传 argv、不经 shell，则无此解释器，退化为“参数注入”。
- **MCP 里的样子**：包命令行工具的 server 把某参数直接插进 shell 命令串。
- **危害**：**远程命令执行（RCE）**——任意代码执行，读写文件、读环境变量/密钥、横向移动、落后门。危害面最高。
- **利用的本质**：让参数值“闭合原命令、追加我方命令”，或用命令替换把我方命令结果嵌回。
- **检测手段（按强弱）**：
  1. **带外回连**：注入让服务端向我方 token 域名发 DNS/HTTP 请求的命令，收到带 token 回连即确认。依赖目标出网。
  2. **带内回显**：注入输出唯一标记（canary）的命令，在响应或报错正文里找标记。网络无关，常比带外更稳。
  3. **时间延迟（盲判）**：注入可控延时，统计响应时间（多次重复 + 阈值去抖）。完全不需出网。
  4. **求值差分**：让 shell 算一个只有真执行才会出现的结果，看是否回现——区分“真执行”与“原样回显”。
  5. **错误指纹**：shell 报错（`sh: xxx: not found`）证明进了 shell、有时证明注入被解析。
  6. **崩溃/可用性**：服务被打到无响应即一个发现（不用破坏性命令，只观察挂起）。

## 2. 参数注入（程序 argv 选项解析边界）

- **原理**：参数作为 argv 安全传入（无 shell，shell 元字符无效），但值以 `-`/`--` 开头，程序自身的**选项解析器**把它当成一个新的命令行**选项/开关**，而非位置参数。
- **MCP 里的样子**：即使 server 用 execFile 规避了命令注入，只要把可控值放进 argv 且未校验前导 `-`，攻击者就能偷塞危险选项。
- **典型例子**：
  - git：`git clone <用户URL> <目录>`，URL 填成 `--upload-pack=<某命令>` → 克隆时执行攻击者程序 → RCE（无 shell 也 RCE，即 2.1.5 后那条 argument-injection 公告的本质）。
  - curl：`curl <用户URL>`，URL 填成“写文件选项 + 路径” → 任意文件写。
  - grep：`grep <用户关键词> file`，关键词以 `-` 开头 → 变成 grep 开关（如从某文件读模式）。
- **危害**：取决于程序有哪些危险选项——写/读任意文件、指定上游、触发网络、执行钩子、间接 RCE。常是“规避了命令注入”的 server 残留的真实漏洞。
- **利用的本质**：让数据从“位置参数”升格为“选项”，打开本不该暴露的功能。
- **常见修复**：用户值前加 `--`（选项结束符），或拒绝以 `-` 开头的值。判定可反推：缺 `--` 分隔符即高度可疑。
- **检测手段**：
  1. **良性独特输出差分（黄金判定）**：注入无害但输出极具特征的选项（如 `--version`/`--help`），响应里出现版本/帮助特征文本即铁证参数被当选项解析。不需出网、几乎零破坏。
  2. **“未知选项”报错指纹**：注入不存在的选项，得到程序 “unknown option” 类报错，说明字符串抵达 argv 并被当选项解析（证“可达 + 可注入”）。
  3. **文件副作用 + 跨工具 canary**：诱导程序用某选项写出已知内容的 canary 文件，用另一个工具读回验证。
  4. **接受 vs 拒绝差分**：合法值与带选项值行为分化即证据。
  5. **带外回连**：仅当某选项能触发网络时适用，非通用首选。

## 3. 路径穿越（文件系统路径解析边界）

- **原理**：参数作为路径使用，预期落在某基目录内，但攻击者用 `../` 回溯、绝对路径或编码（`%2e%2e`、`..%2f`、`....//`）让路径解析到基目录之外。
- **MCP 里的样子**：任何“读/写文件、列目录、导出到路径”的工具，若未规范化 + 基目录约束。
- **危害**：任意文件读（配置、密钥、`/etc` 敏感文件、源码）或任意文件写（覆盖配置、写入可执行文件 → 升级 RCE）。
- **利用的本质**：突破“基目录”边界，把相对路径解析到边界外。
- **检测手段**：
  1. **读到真实文件内容（本项目采用）**：实际检测时直接用穿越去读真实存在的标准系统文件（如 `/etc/passwd`、`/etc/hostname`），用内容签名匹配确认越界。比先种 canary 更直接、PoC 更有说服力。
     - **伦理底线**：只读“证明越界所需”的标准文件作为信号，不批量抓取真正的敏感密钥；确认成立即止。
  2. **写穿越 + 跨工具读回**：用写工具经穿越写到另一工具能读到的位置，再读回。MCP 读写并存的特有强通道。
  3. **差分/深度递增**：穿越路径 vs 合法路径的内容或报错不同；逐步加 `../` 深度至行为变化。
  4. **错误指纹**：报错泄露解析后的绝对路径（`ENOENT: /real/abs/path`），证明穿越被真实解析到基目录外。
  5. **编码绕过探针**：对编码变体做差分，既测穿越也测过滤可否绕。

## 4. SSRF / 服务端请求伪造（网络发起边界）

- **原理**：参数是 URL/主机，服务端据此主动发起网络请求。攻击者把目标改成“服务端够得到、外部够不到”的地址（回环 `127.0.0.1`、云元数据 `169.254.169.254`、内网段、内部端口），借服务端之手访问内网。
- **MCP 里的样子**：“抓取 URL / clone 仓库 / 调 webhook / 拉远程资源”类工具。
- **危害**：访问内网服务、窃取云元数据临时凭证、探测内网、打内部未鉴权接口；全读型可读回响应，危害更大。
- **利用的本质**：**越过信任边界**——让内网信任域里的服务端替攻击者代访它本不该访问的目标。
- **检测手段（重点：不能只靠回连）**：
  1. **信任边界差分（核心判定）**：目标设成只有服务端够得到的内网/回环/元数据地址，与良性外部地址对照；只有“内网目标”产生可区分反应才算真正越界 = 真 SSRF。天然解决“本职功能（如 git_clone.url）被误报成 SSRF”。
  2. **响应回带（全读型，最强）**：被抓取内容直接出现在响应里。
  3. **带外回连**：服务端访问我方 token URL，收到带 token 回连证明“确实发起请求”——**必须配合信任边界判别**，否则抓 URL 本就是功能，回连不等于漏洞。
  4. **时序差分**：内网存在但被过滤的地址挂起/超时，不存在的地址快速失败——以响应时间区分内网可达性（盲判）。
  5. **重定向 / DNS 变换探针（进阶）**：绕过“仅校验首个 URL”的防护。

## 5.（第二阶段）查询注入 —— 以 SQL 为代表（查询语言解析边界）

- **原理**：参数拼进 SQL（或 NoSQL/其它查询语言），突破数据字面量进入查询结构。
- **危害**：拖库、绕过鉴权、改写数据，部分场景可升级到命令执行。
- **检测手段**：布尔差分（真/假条件返回不同结果）、错误型（畸形输入触发 DB 语法错指纹）、时间盲注（条件延时）、联合查询/带外（进阶）。
- 判定原语与前四类高度复用，扩起来是“填矩阵”的增量。

## 6.（第二阶段）代码注入（语言解释器 / eval 边界）

- **原理**：参数被当服务端语言代码求值（eval/模板/反序列化到可执行）。
- **危害**：等同 RCE。
- **检测手段**：求值差分（算表达式看结果回现）、时间延迟（sleep）、带外回连、语言堆栈报错指纹。

---

## 七种可复用的判定原语

把所有检测手段去重，只有七种可复用原语，每类漏洞是从中选若干组合：

1. 带外回连　2. 带内回显　3. 差分/对照　4. 时间延迟　5. 跨工具 canary　6. 错误指纹　7. 崩溃/可用性

---

## 矩阵：六类漏洞 × 七种判定原语

单元格 = 证据强度 + 要点。图例：◎ 铁证（单发即可确认）｜○ 可证（需差分或重复，成立即确认）｜△ 弱证（旁证）｜— 不适用。

| 漏洞类型＼判定原语 | 带外回连 | 带内回显 | 差分/对照 | 时间延迟 | 跨工具canary | 错误指纹 | 崩溃 |
|---|---|---|---|---|---|---|---|
| **命令注入** | ◎ 需出网 | ◎ 回显canary | ○ 求值差分 | ○ 盲时延 | ○ 写文件读回 | △ shell报错 | △ 挂起 |
| **参数注入** | △ 仅网络类选项 | ◎ `--version`特征输出 | ○ 接受/行为差分 | △ 仅延时类选项 | ◎ 选项写文件读回 | ○ unknown option | △ |
| **路径穿越** | — | ◎ 读到真实文件内容 | ○ 越界/深度差分 | — | ◎ 写穿越+读回 | ○ 泄露解析后绝对路径 | △ |
| **SSRF** | ◎ 须配边界差分 | ◎ 全读型回带内容 | ◎ 信任边界差分(核心) | ○ 内网时序 | △ | ○ 内网连通性报错 | △ |
| **查询注入(SQL)** | ○ DBMS相关 | ○ 错误/联合取数 | ◎ 布尔差分(核心) | ◎ 时间盲注(核心) | △ 写行读回 | ◎ DB语法错指纹 | △ |
| **代码注入** | ◎ | ◎ 求值结果回显 | ◎ 算式差分 | ◎ sleep | ○ 写文件读回 | ○ 语言堆栈 | △ |

### 每种判定原语的固有属性（选通道的决策依据）

| 判定原语 | 依赖出网 | 需配套读/写工具 | 误报风险 | 关键约束 |
|---|---|---|---|---|
| 带外回连 | **是** | 否 | 中（本职功能也会回连） | token 唯一；SSRF 须配边界差分 |
| 带内回显 | 否 | 否 | 低 | 唯一 canary 精确匹配 |
| 差分/对照 | 否 | 否 | 低 | 必须带良性对照 |
| 时间延迟 | 否 | 否 | 中（网络抖动） | N 次重复 + 阈值去抖 |
| 跨工具 canary | 否 | **是** | 极低 | 需存在配套读/写工具 |
| 错误指纹 | 否 | 否 | 中（依赖实现措辞） | 多作旁证，不单独定案 |
| 崩溃/可用性 | 否 | 否 | 中（可能偶发） | 需存活探测复核 |

### 两个结论

1. 几乎每类漏洞都有**不依赖出网**的强判定（带内回显 / 差分 / 跨工具 canary）——现在只押“带外回连”是极大浪费，也是 OOB 被禁环境整类失明的根因。
2. **差分**几乎覆盖所有类型，应作为判定引擎的**骨架**：永远带一个良性对照，只认二者稳定分化——这同时带来语义正确性（解决 SSRF 信任边界误报），且不依赖出网。
