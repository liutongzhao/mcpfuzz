# 序列构建智能体设计（草案）

> 方案架构中「模块 5 编排器」里**序列构建（发射台）**的重做。把原来「大模型一次性看描述规划前置序列」的开环做法，换成一个**目标明确、闭环实跑**的智能体：真的去用这个 MCP，把目标工具走到可合法调用的状态，并产出可复现的调用序列。纯架构设计，不含实现代码、不改现有代码。
>
> 关联：`docs/判定引擎模块设计.md`（触达判定/五态）、`docs/Sink推断模块设计.md`、`docs/载荷合成模块设计.md`。

## 1. 模块定位与职责

**职责**：给定一个目标工具，自动探索并产出一条**调用序列（配方）**——前置工具的顺序、每步参数、以及步间的数据依赖，使目标工具能以一整套**合法参数**被调通。

**要解决的问题**：现状是大模型纯看描述一次性猜前置，开环、无执行反馈，常在真正测时才发现「前置即失败、到不了目标工具」，白跑且被误记。改为智能体闭环实跑，边调边看边修。

**边界（两道约束，不可破）**：
- **只管良性可达**：只用**良性值**把目标工具带到「能正常调用」的就绪状态，**不注入载荷、不判漏洞**——大模型仍不进判定回路。
- **产物录制-回放**：探索可不确定，但走通的序列**固化成具体配方**，真实攻击与复现**回放**配方、用自家 driver 确定性执行，不再实时摸索。

## 2. 基本形态

- **发现阶段用框架**：`LangGraph` 预制 ReAct 智能体 + `langchain-mcp-adapters` 把目标 MCP 的工具加载成智能体可调工具（Streamable HTTP）。
- **分工**：
  - 框架白送：**智能体循环 + MCP 工具接入**；
  - 我们自己写：**终止/控制层、配方提取（从执行轨迹）、良性边界（系统提示+仅给该服务工具）**；
  - **回放不经智能体**：按配方用现有 driver 确定性执行。框架只活在发现阶段，其不确定性被隔离在此。

## 3. 输入 / 输出（数据契约）

**输入**
- `target_tool`：目标工具规格，含其**必填参数集**（来自解析器，用于算目标相对进展）；
- `tool_catalog`：该 MCP 服务的全部工具（供发现 producer、解依赖）；
- MCP 端点/会话；
- `settings`：停滞窗口 K、硬预算上限、墙钟上限等。

**输出（二选一）**
- **成功 → SequenceRecipe（配方）**：
  - `steps`：有序步骤列表，每步 `{tool, args}`；
  - `args` 每项：**常量值**（回放照抄）或**依赖边**（引用前面某步输出 + 提取规则，回放时**重新取值**）；
  - `target_call`：目标工具的合法基线实参（攻击时只替换被测的那一个参数，其余照此）。
- **失败 → UnreachableResult**：`reason`（见 §5 的退出原因）+ 诊断信息。

## 4. 智能体循环与控制层

- **循环**：ReAct 调用（框架）→ 每步执行一个工具调用、拿到返回/报错 → **控制层更新进展状态并判是否该停**。
- **进展状态（控制层维护，我们写）**：
  - `satisfied`：目标工具必填参数里**已凑齐合法值**的集合；
  - `ok_calls`：已成功（非校验错）调用过的工具集；
  - `tried`：已尝试的 `(工具, 规范化参数)` + 报错的**状态哈希集**（查循环）；
  - `producers`：已发现的「某输出可填某参数」的依赖边。
- **控制层组件**：进展度计算、错误分类器、producer/死胡同预判、循环检测、预算兜底——这些正是框架不给、属于我们的核心逻辑。

## 5. 退出机制（分层策略，任一触发即停）

**主信号：目标相对进展** = `satisfied / 目标必填参数总数`。在涨=有进展；连续 K 步不涨=停滞。非机械、相对目标。

| 优先 | 触发 | 结果 / 退出原因 |
|---|---|---|
| ✅ | 目标工具以合法参数调通、返回**非前置校验类报错**（触达） | **成功** → 产出配方 |
| 🛑 | 终止类错误（认证/权限/工具不存在/功能被禁） | 不可达：`terminal_error` |
| 🛑 | 死胡同：某必填输入在工具集中**无任何 producer** | 不可达：`no_producer` |
| 🛑 | 目标相对进展连续 K 步不涨 / 停滞 | 放弃：`stagnation` |
| 🛑 | 循环：重访已试失败状态 | 放弃：`loop` |
| 🛑 | 智能体自主放弃（须经进展信号佐证，不单信 LLM） | 放弃：`self_giveup` |
| 🛑 | 硬预算 / 墙钟上限（仅兜底） | 放弃：`budget` |

**原则**：「停」是有理由的决策，由**进展度 + 错误语义**驱动；数字上限只是安全网。每种退出带**结构化原因**。

**退出原因 → 五态映射**：
- 成功：产出配方 → 进入攻击+判定（目标参数不会再因前置失败被误判）；
- 任何「不可达/放弃」：意味着**发射台没搭起来**、目标工具无法被合法调用 → 判 **未测成（SKIPPED）**，并把 `reason` 写进结论；
- （区分）配方成功、但攻击阶段某条载荷打不到 sink → 那是判定模块的 **未触达（UNREACHED）**，与此处无关。

## 6. 配方提取与录制-回放

- **从执行轨迹抽配方，不让 LLM 自述**：读智能体真实调用过的 tool-call 轨迹（框架暴露的消息/中间步），取**走通路径**上的步骤。
- **常量 vs 动态值**：
  - 常量（如固定字符串）→ 配方存字面值；
  - 动态值（如新建资源返回的 id，每次不同）→ 配方存**依赖边**（源步骤 + 提取规则），**回放时重新取值**。
- **依赖边推断**：主用**值匹配**（后续调用的某参数值 = 之前某步输出的子串 → 推断一条边），LLM 事后标注兜底。（细节见 §9。）
- **回放**：`编排器` 按配方用现有 driver 顺序执行前置步骤、回填动态值，最后把目标工具基线实参就绪，交给判定。
- **缓存**：配方按 `(服务, 目标工具)` 缓存，**发现成本只在首次付一次**，之后回放零 LLM 调用。

## 7. 与其它模块接口

- **解析器 →**：提供目标工具的必填参数集（算进展）与工具目录（找 producer）。
- **→ 判定**：成功信号（目标以合法基线调通、非校验错）与判定的「触达判定（reached?）」**同一口径**；失败 → SKIPPED + reason。
- **→ 攻击阶段**：交付配方；攻击时回放前置、替换被测参数为载荷、其余沿用 `target_call`。
- **Sink/载荷**：不直接耦合；本模块只负责「把目标工具合法调通」，与测什么漏洞无关。

## 8. 可复现与可测

- **不确定性隔离**：发现阶段可不确定；回放确定性、可复现。
- **指标**：触达成功率、平均步数、发现阶段 LLM 调用数、各失败原因占比。
- **消融**：序列构建智能体 vs 大模型一次性规划 vs 仅看 schema——因为它是独立组件，可单独做实验衡量「序列构建」这一步的增益。

## 9. 待细化难点

- **依赖边推断**：值匹配的误判（巧合子串）与多候选；是否需要智能体显式声明产出→输入的映射。
- **资源副作用**：良性探索会创建资源（仓库/文件）；是否记录并清理，避免污染目标。
- **停滞窗口 K 与进展度定义**：对不同复杂度目标如何自适应，避免切早/切晚。
- **终止类错误的判定词表**：如何稳健地把「认证/权限/不存在/禁用」从可恢复错误里分出来（措辞依赖实现）。
- **成本**：闭环发现比一次性猜贵，靠缓存+预算上限控住；首扫整体耗时需评估。

## 10. 与现有代码的对应（演进方向，不现在改）

- 现有「大模型一次性规划前置」的 planner → 由序列构建智能体替代（发现阶段）；
- 现有 `executor` 的发射台构建循环 → 改为「**按配方回放**」（确定性、用 driver）；
- 新增：`agent/` 子包（LangGraph + mcp-adapters 封装、控制层、配方提取）、SequenceRecipe/UnreachableResult 数据结构、配方缓存；
- 遵循 baseline 版计划：方案级改动待基线对比后再落代码。
