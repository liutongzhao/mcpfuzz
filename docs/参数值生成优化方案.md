# 参数值生成优化方案（第二类 ①+②）

> 目标：解决第二类里 **P2（合法填充值，死填 "test"）** 和 **P4（约束感知载荷，固定模板被校验挡下）**。
> 核心判断：P2 与 P4 本质是同一件事——**生成一个满足参数声明约束的值**（P4 只多一步"在合法骨架里嵌载荷"）。因此建**一个共享的"约束感知值生成器"**，填充与载荷都调它。
> 前置：现有 `catalog.Param` 没提取 `pattern/format/长度/数值界/minItems`，不先抽进来则下游无从感知——这是 ① 要做的地基。
>
> 关联：[[判定引擎模块设计]]、[[载荷合成模块设计]]、[[序列构建智能体设计]]；本方案不含 P5（类型探测）与依赖边（from_step），那两项另议。

---

## ① Catalog 约束提取（地基，低风险）

### 改 `catalog.Param`（`catalog.py`）

在现有字段（path/type/required/description/enum/default/example/item_type）基础上新增：

```python
pattern: str | None = None          # JSON Schema pattern（正则）
str_format: str | None = None       # format：uuid/date-time/date/email/uri/ipv4/ipv6/hostname/...
min_length: int | None = None       # minLength
max_length: int | None = None       # maxLength
minimum: float | None = None        # minimum / exclusiveMinimum(数值形)
maximum: float | None = None        # maximum / exclusiveMaximum(数值形)
exclusive_min: bool = False
exclusive_max: bool = False
multiple_of: float | None = None    # multipleOf
min_items: int | None = None        # minItems
max_items: int | None = None        # maxItems
```

### 改 `flatten_schema`（`catalog.py`）

在构造每个 `Param` 的三处（object 叶子跳过、array 分支、普通分支）统一补一个 `_constraints(sub)` 读取并透传：

```python
def _constraints(sub: dict) -> dict:
    mn, emn = sub.get("minimum"), sub.get("exclusiveMinimum")
    mx, emx = sub.get("maximum"), sub.get("exclusiveMaximum")
    # draft-07: exclusiveMinimum 是数值；draft-04: 是布尔(配合 minimum)
    minimum = mn if mn is not None else (emn if isinstance(emn, (int, float)) else None)
    maximum = mx if mx is not None else (emx if isinstance(emx, (int, float)) else None)
    return dict(
        pattern=sub.get("pattern"),
        str_format=sub.get("format"),
        min_length=sub.get("minLength"),
        max_length=sub.get("maxLength"),
        minimum=minimum,
        maximum=maximum,
        exclusive_min=(emn is True) or (mn is None and isinstance(emn, (int, float))),
        exclusive_max=(emx is True) or (mx is None and isinstance(emx, (int, float))),
        multiple_of=sub.get("multipleOf"),
        min_items=sub.get("minItems"),
        max_items=sub.get("maxItems"),
    )
```

风险：仅"多读几个 key"，不改任何既有行为。写完后用现有服务的 catalog.json 验证字段被填上。

## ② 约束感知值生成器（核心）

新模块 `mcpfuzz/valuegen.py`，对外两个入口：

```python
def benign_value(param) -> object:
    """产一个满足参数约束的【良性】值（P2 用）。确定性优先，LLM 只兜底。"""

def inject_value(param, payload: str) -> object | None:
    """把攻击片段 payload 嵌进一个满足约束的【合法骨架】（P4 用）。
    参数被完全锁死（uuid / 严格枚举 / 纯数值 / 无自由位的 pattern）→ 返回 None
    （表示此参数无法承载该类注入，如实跳过，不强塞、不算漏报）。"""
```

### 2.1 `benign_value` 优先级阶梯（确定性优先）

按序尝试，命中即返回；每一步产出的值最后统一过 `_enforce(param, v)`（见 2.3）做长度/数值界收尾：

1. **enum** → `enum[0]`（封闭集，只能取其中之一）
2. **example** → 若与 type 相容则用
3. **default** → 用（保留现有启发：路径型且 default 是 `.`/``/`cwd` 则改 `/tmp/mcpfuzz_probe`）
4. **format 生成器**（`str_format` 命中查表）：
   | format | 良性值 |
   |---|---|
   | uuid | 固定 `00000000-0000-4000-8000-000000000000` |
   | date-time | 当前 ISO-8601，如 `2026-01-01T00:00:00Z` |
   | date | `2026-01-01` |
   | time | `00:00:00` |
   | email | `test@example.com` |
   | uri / url / iri | `http://example.com/` |
   | hostname | `example.com` |
   | ipv4 | `127.0.0.1` |
   | ipv6 | `::1` |
   | duration | `PT1S` |
   | byte(base64) | `dGVzdA==` |
5. **pattern 生成器**（有 `pattern`）：
   - 先抽**字面前缀**：对 `^<literal>...` 形态取出 `<literal>`（覆盖最常见的"must start with X"，零依赖）。
   - 前缀 + 满足剩余长度的填充（`a` 重复）；能满足就返回。
   - 复杂正则（非纯前缀）→ 可选用小库 `exrex`/`rstr.xeger` 生成一个匹配串；**首版可不引库**，复杂 pattern 落到第 6/7 步。
6. **名字/描述启发**（保留现有 `_fallback_literal` 的）：路径名→`/tmp/mcpfuzz_probe`；url 名→`http://example.com/`。
7. **类型兜底**：`string→"test" / integer→1 / number→1 / boolean→True / array→[] / object→{}`。
8. **LLM 兜底（opt-in、带缓存）**：仅当"**schema 无约束但描述里有语义约束**"（如描述说 "a valid AWS region"），或收到"该值被服务端拒"的反馈信号时，才用 `llmclient.complete` 让大模型据"参数名+类型+描述"产一个良性值；按 `(tool,param,签名)` 缓存，避免每参数都掏 LLM。

### 2.2 `inject_value(param, payload)` —— P4 的"合法骨架 + 注入"

判定该参数**有没有"自由位"能放载荷**：

- `string` 且**无 pattern/format/enum** → 直接返回 payload（现状，但先过 `_enforce` 补足 `min_length`）。
- 有 `min_length` → 载荷不足则右侧 pad 到够长（注入片段在前，pad 在后）。
- `pattern` 为"字面前缀 + 自由尾"（`^PREFIX`，无 `$` 锚或尾部可变）→ 返回 `PREFIX + payload`。
- `pattern` 完全锚死、无自由位 → 返回 **None**（无法注入）。
- `str_format` ∈ {uuid,date,date-time,email,ipv4,...} 这类**刚性格式** → 返回 **None**（注入不可能，honest skip）。
- `enum` → 返回 **None**（只能取枚举值）。
- `number/integer/boolean` → 返回 **None**（字符串注入进不去；"宽松校验服务端"由 P5 类型探测单独处理，不在本模块强塞）。
- `object/array` → 交给形状逻辑（见 2.4）。

> 要点：**返回 None = "此参数这条类别打不进，如实判未触达"**，不是缺陷。把"真的打不进"和"我们没构造对"彻底分开。

### 2.3 `_enforce(param, v)` 收尾

- 字符串：不足 `min_length` 右侧补 `a`；超 `max_length` 截断（注入片段尽量保留在前）。
- 数值：夹入 `[minimum, maximum]`（含 exclusive 调整），取整（integer），向 `multiple_of` 对齐。
- 保证产出的良性值本身合法（否则 benign_value 自己就被拒）。

### 2.4 形状（并入 P3 遗留）

`inject_value`/`benign_value` 对 `array`/`object` 产出结构值：
- `array`（字符串元素）：`[v]`，`min_items>1` 则重复到够数。
- `object`（自由 record）：`{key: v}`；**P4 增补 key 位探针**：对 object 另发一个 `{v_payload: "x"}`（载荷放 **key**），覆盖 env 变量名/HTTP 头名型 sink。
- 定型对象/嵌套：首版维持"自由 record"处理，更完整的嵌套塑形记为后续。

## ③ 接口改造（最小触碰点）

| 位置 | 现状 | 改为 |
|---|---|---|
| `planner._fallback_literal(param)` | 固定优先级 + 死填 test | 直接 `return valuegen.benign_value(param)`（把原有路径/url 启发并入阶梯第 6 步） |
| 载荷放置（`executor._shaped_args` 或 `payload/core._build`） | 只按 array/object 塑形 | 对有约束的参数，用 `valuegen.inject_value(param, 模板值)` 产合法骨架；返回 None 则**跳过该载荷** |

**一处 plumbing**：`_shaped_args` 现在只拿到 `prior`（只有 `param_type`）。要约束感知，需把 **Param 的约束**传到攻击循环——方案：给 `ParamSinkPrior` 增带约束字段（在 `sink/core.py` 构造 prior 时从 Param 透传），或在 executor 里按 `param_path` 从 catalog 反查 Param。推荐前者（随 prior 一路带下去，和已有 `param_type` 同处）。

## ④ 边界与取舍（明确不做/honest skip）

- **刚性约束 = 如实未触达**：uuid/严格枚举/纯数值/锚死 pattern 的参数，注入本就不可能 → `inject_value` 返 None，判未触达是**正确**的，不强塞。
- **LLM 只兜底**：确定性阶梯优先；LLM 仅用于"描述有、schema 无"的语义约束，带缓存。
- **依赖**：format 手写查表（零依赖）；pattern 先做"字面前缀抽取"（零依赖），复杂正则再议是否引 `exrex`/`rstr`。
- **不在本方案**：P5 类型探测、from_step 依赖边、完整嵌套/多元素数组塑形——各自单列。

---

## ⑤ 验证与度量（方案级改动 → 前后对比）

做完 ①+② 后，**用改好的工具重跑第一批**，与"P1 修复后基线"对比（即论文消融）：

- **主指标**：参数级 `unreached` 数应下降；其中重点看两个子集：
  - **格式/pattern 受限的目标参数**（现在被原始载荷打掉的）→ 期望转为"到达 sink"或"确认"；
  - **兄弟参数填充被拒**（P6 已能用 `_blamed_param` 标出）→ 期望这些调用不再整体被挡。
- **次指标**：`reached(clean+confirmed)` 上升；若有 unreached→confirmed，逐个核实（真漏洞）。
- **防回归**：确认数不应因乱塞合法骨架而出现新的误报；object key 位探针命中要人工复核。
- **成本**：LLM 兜底调用次数（应很低，确定性阶梯兜住大部分）。

## 实现顺序

1. **①**（catalog 补约束提取）——地基，先做、最低风险。
2. **②的 benign_value + 接 `_fallback_literal`**（P2）——先让填充值变合法。
3. **②的 inject_value + 接载荷放置 + prior 带约束**（P4）——再让载荷约束感知。
4. 重跑第一批做前后对比（⑤）。
