# 数据集构建方案

> 本文件是两个数据集的权威构建方案,供后续采集/标注/部署对照执行。
> 配套:`docs/论文实验计划.md`(实验总规划)、`data/analysis/report.txt`(CVE 子集统计)。
> 口径前提见记忆「论文结果口径」:论文结果只落二元、只报人工验证为真、实现细节不进正文。

---

## 0. 两个数据集,性质完全不同,不要混

| | 数据集 A:Ground-truth 基准集 | 数据集 B:大规模采集集 |
|---|---|---|
| 用途 | 量**我们的工具**(E1 准确率 + 消融) | 量**生态**(E3 测量) |
| 标签 | **有**,且独立核实(CVE/手工 PoC) | **无**(或只有工具自己的判决) |
| 规模 | 小(几十个服务),但标得准 | 万级,但不逐个标 |
| 成败标准 | 标签可信、不循环 | 总体清晰、覆盖率可量化 |

**铁律(防循环论证)**:绝不在 B 上算召回率——我们不知道 B 的真值。B 只能算流行度 + 抽子样本人工验证。**真值标注只在 A 上做。**

**支持的漏洞类(2026-11-02 锁定 4 类)**:命令注入 / 参数注入 / 路径穿越 / SSRF。
(框架枚举 6 条注入边界,SQL/代码注入 sink 分类器认得但无载荷电池、暂不支持,本阶段不纳入。)

## 1. 数据集 A:Ground-truth 基准集

### 1.1 用途与打分口径

- **用途**:E1.1 准确率(precision/recall/F1)、E1.2 消融。
- **打分单位 = 参数×类**(最细、与工具判决/真值标签/防御补丁同一层;可向上卷成工具级、服务级粗视图)。
- **漏洞计数单位**(用于报"发现 N 个"):一个漏洞 = 一个根因 = 一次修复能堵掉的缺陷;同服务同类同根因 → 并成 1。
- **注意两套口径**:A 这里要算负样本和误报(证明工具本身准);E3 大规模测量才用"只报人工验证为真"的二元口径。两者别混。

### 1.2 骨架:漏洞版 vs 修复版 配对差分

整个 A 的地基是一对对**同服务、同参数、只差一个补丁**的样本:

```
同一个 CVE MCP
 ├─ 漏洞版(CVE 指定版本)        → 正样本:该参数应报"有"
 └─ 修复版(advisory 指定 fixed 版) → 负样本:同参数应报"无"
```

正样本量召回,配对修复版量精度/误报,难度匹配。工具能否区分"打了补丁 / 没打补丁",直接证明它判的是真漏洞而非乱喊。**优先搭这部分。**

### 1.3 正样本来源

1. **CVE 背书(主干)**:来自 `data/analysis/target_subset.jsonl`,独立、非循环。命令/路径/SSRF 在 CVE 里充足。
2. **自采补齐(必须)**:**参数注入在 CVE 里几乎为空**(全集仅 10 条,过完可部署筛子基本归零),用**我们自己确认且独立手工 PoC 过**的补进来(如 MCPVULN-003),标签来源记"手工 PoC"。保证最强的差异化类在表上不空白。

### 1.4 负样本来源(精度/误报的唯一来源)

1. **修复版配对(主体)**:1.2 的 fixed 版本。补丁若把工具/参数直接删了则该负样本不可用,换别的。
2. **附带干净**:正样本服务里其他参数,核实确为干净。
3. **难负例(少量,仅 E1 内部用、不进论文正文)**——每类对应一项核心机制的"对抗样本":
   - **回显型(echo)** → 戳求值回显 oracle 抗误报;
   - **本职功能型(shell-exec)** → 戳"本职功能 vs 真漏洞"判定;
   - **正确转义型** → 戳不把防护好的误报;
   - (可派生:合法内网 URL 戳 SSRF 不误报;天然抖动时延戳时序通道不误报。)

### 1.5 构建六步

1. **筛正样本候选**:在 581 条里过滤——仅 4 类;有包信息(先砍 331 条无包的);开源 + 能钉精确漏洞版本 + 不依赖外部 SaaS;黑盒可检测(yes/partial)。
2. **部署做可用性筛**:候选经网关起起来,确认漏洞版能启动、tools/list 正常;起不来的出局并记原因。
3. **标正样本**:人工映射 CVE → (工具,参数,类),记确切漏洞参数;一 CVE 多参数 → 一个漏洞、多条参数标签。
4. **配修复版负样本**:拉 advisory 的 fixed 版本,同参数做负样本。
5. **补参数注入正样本**:自采手工 PoC 过的补入。
6. **加难负例 + 冻结**:少量难负例;pin 全部版本、归档镜像、落 env.lock、记快照日期与标注人。

### 1.6 标注协议

- 双人独立标 + 分歧仲裁,或 标注人 + 源码核实 双证。
- 每条标签记:来源(CVE advisory / 源码核实 / 手工 PoC)、证据、标注人、`dangerous_by_design` 标志。
- **本职功能判定标准须先成文**,再开始标注(属前置件)。

### 1.7 E1 指标

标注/打分单位 = (服务@版本, 工具, 参数, 类)。混淆矩阵:

| | 真有漏洞 | 真干净 |
|---|---|---|
| 工具报"有" | TP | FP(靠负样本) |
| 工具报"无" | FN | TN(靠负样本) |

- 精度 = TP/(TP+FP);召回 = TP/(TP+FN);F1;误报率 = FP/(FP+TN)。**全部按 4 类分报。**
- **触达率单列**:该测到的参数里实际把载荷打进 sink 的比例;FN 拆成"测了判错"与"未触达"(消融里序列构建/约束感知撬的是后者)。
- **TN 分母只算真正的注入候选参数**(自由文本/字符串),排除枚举/布尔/定长数字等结构惰性参数,免得误报率被稀释虚低。
- **多轮跑**,每个指标报均值 ± 离散度(工具 LLM 驱动会抖)。
- **标签不完整安全阀**:工具在"标为干净"参数上报"有" → 先人工核再判 FP;若实为真漏洞则改标签(我们标漏了),不算工具误报。

### 1.8 规模(定结构,不纠结精确数)

- 正样本:命令/路径/SSRF 靠 CVE 各凑够能分类报召回的量;参数注入靠自采补。
- 负样本:以修复版配对为主体 + 附带干净 + 少量难负例。
- 不追总数,追:**4 类都有正样本 + 每个正样本尽量有配对负样本**。

## 2. 数据集 B:大规模 MCP 采集集

### 2.1 用途与两层结构

- **用途**:E3 生态测量(流行度、严重度分布、受影响规模)。
- 测试床沿用 mcphub 网关(论文不细述基础设施);stdio / http 都接入、都测。

### 2.2 层一:全量目录(测量的分母)

多源采集(官方 registry、Smithery、Glama、PulseMCP、npm、PyPI、GitHub 等),每个服务登记元数据:来源 registry(可多个)、包 id、版本、`command+args`、transport(stdio/http)、语言、工具数、env/密钥依赖、流行度(stars/下载量,如可得)、描述。

- **去重键 = 包身份**(npm 名@版本 / GitHub repo / command+args 指纹)。
- 输出两个数:**条目数(listings)** 与 **唯一服务数(= 总体 N)**。流行度一律按 N 算。

### 2.3 层二:入库校验门(覆盖率的来源)

**剔除不可测的,但每个剔除都带原因记账**(防幸存者偏差;这张漏斗本身就是 E3.1 的核心测量图):

```
采集去重 N
 ├─ 装不起来 / 拉不到 / 缺密钥     → 记原因,出局
 ├─ 起来了但 tools/list 为空       → 记原因,出局
 └─ 起来且有工具                  → 入库(可检测总体 M) → 扫描 → 判决
```

### 2.4 多机并行账本

- 冻结 batch manifest:哪个包在哪台机、哪批次。
- 每台机一个 mcphub 实例管互斥子集;**汇总时按包身份再去一次重**(同包可能跨机/跨 registry 重复),否则确认漏洞数虚高。
- 每批记快照日期 + env.lock;破坏性 sink 只用非破坏性证明(echo/标记/OOB),每批扫完 `reload` 重置。
- sink 推断按工具 schema 指纹缓存(万级下近乎必需,砍 LLM 成本)。

### 2.5 A 与 B 的交叉

- B 里 CVE 背书、能部署的服务可抽出来喂给 A 做正样本(单向:B→A 时补独立标签)。
- **E3.2 人工验证子样本**(在 B 的扫描产物上抽样核 TP/FP)是第三样东西,不等于 A,别混用来算召回。

## 3. 贯穿两个数据集的要求

- **冻结工具版本**:定一个 tag,A、B 全程用同一版本,中途不改代码。
- **可复现**:版本 pin、env.lock、原始输出归档、快照日期、`regenerate_figures.sh`。
- **伦理**:自建测试床、不打第三方线上;真漏洞负责任披露 + 时间线;论文不写完整 CVE 编号;填好 Generative AI 使用字段。
