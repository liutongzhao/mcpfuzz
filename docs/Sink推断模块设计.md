# Sink 推断模块设计（草案）

> 方案架构中的「模块 3 Sink 推断」。它是地基：载荷合成、编排、判定都建立在它的产出之上。本文件把讨论敲定的设计固化下来，纯架构设计，不含实现代码、不改现有代码。
>
> 关联：`docs/判定方法论.md`、`docs/判定引擎模块设计.md`、`docs/漏洞类型与检测手段.md`。

## 1. 模块定位与职责

**职责**：对目标服务每个工具的每个参数，产出一份「该参数可能通向哪几条注入边界、各有多强」的**软先验**，供下游排序与分配预算。

**明确不做**：
- 不做硬分类、不输出单一标签；
- 不产出「后端是什么程序」这类产物——**程序感知载荷已放弃**，故 Sink 不再需要识别具体后端程序；
- 不决定「测不测某个漏洞类」（下游只按先验排序/分预算，不以先验作闸门）；
- 不做漏洞确认（那是判定模块的事）。

## 2. 核心设计决策（已敲定）

### 2.1 在「注入类别 / 边界」层枚举，不在「后端程序」层
后端程序是开放长尾、不可枚举；但数据最终越过的**危险边界是封闭集合**：命令注入、参数注入、路径穿越、SSRF、查询注入、代码注入（对应 CWE 注入家族）。**枚举放在边界这一层**——有限、可辩护、对没见过的程序也适用。

### 2.2 软先验，不作闸门
产出是封闭集合上的**带权分布（排序）**，不是点估计。下游「只排序、不闸门」：先验高者先测、变体更全；先验低者仍测、预算收敛。确认漏洞时用**命中载荷自身的类别**，不回看参数的首要标签。

### 2.3 地板 + 抬升（核心机制）
- **地板（floor）**：凡「可能携带注入」的参数，对封闭集合里**每一个启用类别都给非零基础权重**。标错/漏标最多降低优先级，**永不把某类清零**。
- **抬升（raise）**：证据只负责把某些类别从地板往上抬。
- **学术表述**：等价于给「参数属于哪类注入」这一隐变量一个**全支撑先验 + 加性平滑（Laplace smoothing）**，推断产出**后验分布**而非点估计；在系统层面是对「分类不确定性」**fail-open**。
- **可证性质**：因每个启用类别权重 ≥ floor > 0，预算分配保证每类至少获得最小载荷集，故**方法召回存在下界，不随分类误差归零**——这是「构造上更强」的形式化落点，可写入论文，无需实验即可论证优于「先分类再只测该类」。

### 2.4 结构预筛（允许事实性硬过滤）
语义类别不许卡死，但**结构惰性参数可以卡**：枚举、布尔、严格范围/定长数字等——其值域封闭，**结构上就不可能携带注入**，直接判「惰性、跳过」。这是来自 schema 的**事实**（不是猜），是控成本的主要手段。自由文本（及字符串的数组/对象）→ 进入语义阶段。

### 2.5 单次 LLM + 规则并集（不多次采样）
- 多次采样太费时且已非必要——地板 + 规则并集已提供召回安全网，单次调用召回基本不丢。
- **LLM**：**按工具一次性判**（该工具所有参数 + 六类一起），结构化输出、**逐类独立打分**、**先推理后结论**、**强制引用描述/schema 原文**作依据（引不出原话 → 压回地板）、**低温 + 缓存**。
- **置信**：来自单次内——每类给「高/中/低」且须有证据引用；用 **CVE 数据集离线校准**「高/中/低 → 真实精度」（离线做，不增加在线调用）。
- **规则层**：确定性关键词（名/格式，如 path/url/cmd/ref/host/query、`format: uri`），**每次都跑**，和 LLM 取并集，作为**确定性召回下界**，专捞 LLM 漏网。

### 2.6 阶段范围（PHASE）是范围配置，不是每参数闸门
「本阶段只做 命令注入 / 参数注入 / 路径穿越 / SSRF」（查询注入、代码注入留第二阶段）是**研究范围**层面的开关，允许；它不同于、也不等于对单个参数的 sink 闸门——后者已废除。

## 3. 输出对象：ParamSinkPrior（数据契约）

每个（进入语义阶段的）参数产出：
- `param_path`
- `class_weights`：启用的封闭类别 → 权重（均 ≥ floor）；
- `provenance`：每个被抬升类别的依据（LLM 引用的原话 / 命中的规则），供调试与报告；
- `inert`（结构预筛判定为惰性的参数）：标记跳过原因。

## 4. 推断流程（数据流）

```
工具目录(工具+参数+schema+描述+server名)
      │
      ▼
① 结构预筛：enum/bool/定长数字 → 惰性跳过；自由文本/字符串数组对象 → 继续
      │
      ▼
② 语义抬升(静态)
   ├─ 规则层(确定性)：名/格式关键词 → 抬升对应类别(下界)
   └─ LLM层(工具级·单次·低温·缓存)：逐类打分 + 强制引用 + 置信
   合并：每类权重 = max(floor, 规则抬升, LLM抬升)
      │
      ▼
③ 产出 ParamSinkPrior(类别权重 + provenance) → 缓存
```

## 5. 权重与预算映射（形状，不定死数值）

- floor = 一个小正数 ε（保证非零、可测试）。
- 规则命中 → 至少抬到「中」档。
- LLM：高/中/低 → 高/中/低权重（经 CVE 数据集校准后的档位）。
- 合并：对每类取各来源的 **max（并集语义）**；「说不清/弃权」→ 留在地板附近（广覆盖）。
- 下游预算 ∝ 权重；**floor 保证每个启用类别至少获得最小载荷集**（召回下界的来源）。

## 6. 与下游模块接口

- **→ 载荷合成**：按 `class_weights` 决定为哪些类别生成套件、分配变体预算；floor 保每类最小套件。
- **→ 编排器**：不再按单一 sink 过滤工具/参数；所有非惰性参数都进入测试流程。
- **→ 判定**：先验只排序不闸门；差分探针与判定「触达判定」共用；确认用载荷自身类别。

## 7. 可复现与可测

- **可复现**：LLM 低温 + 缓存 → 基线稳定、可回放。
- **可测**：CVE 数据集既用于**校准**单次置信，又作为**评估集**——把「类别先验的逐类精度/召回」做成 Sink 模块的独立指标，用数据迭代 prompt 与校准（也是一条可写的实验/消融线）。

## 8. 与现有代码的对应（演进方向，不现在改）

- 现有 `SinkLabel(type, confidence)` 列表 + `_sink_of` 取首个 → 演进为 `class_weights` 带权分布（带 floor）；
- 现有 `PHASE1_SINKS` 当「每参数闸门」用 → 降级为「阶段范围配置」，并补入**参数注入**（此前被排除）；
- 新增：结构预筛、规则并集下界、provenance、CVE 校准。
- 遵循 baseline 版计划：方案级改动待基线对比后再落代码。

## 9. 待细化难点

- **抬升的档位→权重映射**与校准的具体标定（依赖 CVE 数据集实测）。
- **结构预筛边界**：哪些「看似受限」的参数其实仍可注入（如带宽松 pattern 的字符串），避免误过滤。
- **规则关键词表**的覆盖与误抬平衡。
