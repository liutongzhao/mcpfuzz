## 0. 论文定位（叙事主线）

**新攻击面（MCP）＋ 生态测量 ＋ oracle 检测方法** 三合一的 research paper。

- **真实攻击者**：可达 MCP 端点者 / 被授予该工具的恶意或被操纵 agent；payoff＝网关容器内 root RCE → 窃取网关凭据、打穿同容器所有 MCP（威胁模型：容器即宿主 + agent 中介）。
- **why now**：MCP 生态爆发式铺开、agent 大量接入第三方 MCP，这个攻击面此前无人系统测过。
- **必须避开的坑**：不能写成"更快的 fuzzer"（工程/USENIX 口味）。**security delta ＝ MCP 新攻击面 + 生态级实证发现 + 求值回显 oracle 方法**。

## 2. 五个研究问题（RQ）与实验

### RQ1 方法可信吗 —— mcpfuzz 准确率
- **E1.1 准确率基准**：建**带标注 ground-truth 基准集**（已知有漏洞 + 已知干净的 MCP，源自 CVE 数据集流程），算 **precision/recall/F1，按漏洞类别分报**。
- **E1.2 消融**：见下方「消融方法论」。**待 ground-truth 基准集就绪后再做**（消融必须在带标注集上跑，无地基则无意义）。

#### 消融方法论（两层结构，2026-11-02 敲定）

**拆分依据（沿"声称的贡献"拆，不沿代码模块拆）**：S&P 消融 isolate 的是"你声称负责增益的组件"。我们六个代码模块（driver/catalog/sink/payload/orchestrator/oracle）里，只有**带贡献声明的四个**进消融，driver/catalog 是基础设施、不进。四个各对应黑盒 MCP 的一个独立挑战：

| 挑战（黑盒 MCP 特有） | 技术（§4 贡献） | 消融换成的"笨版本" |
|---|---|---|
| 无结构规范，参数流向哪条危险边界未知 | Sink 软先验（地板+抬升、边界层枚举） | 关推断，所有载荷族盲打/随机 |
| 载荷在校验层就被拒（类型/格式/兄弟必填） | 约束感知载荷合成 | 固定模板字典，无视约束 |
| 深层 sink 要先把服务带到前置状态 | 序列构建智能体（闭环实跑配方） | 单步，前置参数填死占位 `"test"` |
| "真执行"与"仅输入回显"难区分 | 求值回显 + 差分骨架 oracle | 朴素反射（标记出现即判） |

**两层指标（关键）**：
- **第一层（主干，必须）**：所有变体压在**同一 ground-truth 集、同一主指标**上——**召回 / 确认 TP / F1（含 FP→精度）**。作用是让四个组件在同一把尺上**可比**。这是审稿人认的 "isolating the component responsible for the gain"。
- **第二层（辅助，解释机制）**：每个变体再附一个它最直接撬动的**诊断指标**，解释主指标为什么掉：
  - −求值回显 oracle → 误报率（FP↑）
  - −约束感知载荷 → "因调用被拒"的未触达率
  - −序列构建 → "因缺前置状态"的未触达率 / 可达率
  - −sink 推断 → 每参数请求数 / 首次命中时间（成本）

**三条纪律（防被驳）**：
1. **一轮只切一个组件**，其余全不动；一轮可读出多个指标，但"某指标变化归因某组件"只能来自只切了该组件的那轮。
2. **未触达按原因分桶**（"校验拒" vs "缺前置"），使 约束感知 与 序列构建 两个消融相互独立、不被说成重复。
3. **Sink 推断是 fail-open 特例**：按设计不作闸门，关掉它**召回不该归零、只该让成本爆炸**。故 sink 这一行主指标走**"定预算下召回 + 成本"**轴，并如实写成"它买的是效率不是召回"——与设计文档"召回有下界"的形式化结论一致，硬说它提升召回反而露怯。

**规模**：消融不需万级，在 ground-truth 小集上做（几十个目标即可），要的是对比不是规模。

### RQ2 比现有手段强吗 —— baseline 对比
- **E2 对比**：对比**最强**现有手段——(a) 现有 MCP 扫描器（需 prior-art 调研）、(b) 通用黑盒 fuzzer 适配 MCP、(c) 可选 纯 LLM/静态 baseline。
- 硬性协议：**等 CPU 时间预算（非墙钟）、每配置 ≥5–10 轮、报方差、相同种子语料、unique-bug 用 ground-truth 判重**。
- 指标：漏洞数 / precision / 可达率 / 首次命中时间。

### RQ3 生态有多不安全 —— 头号测量（论文大标题结论）
- **E3.1 总体与抽样**：定义总体（哪个/哪些市场或 registry）、总规模 N、抽样框、纳入标准（如 npx/stdio/能起来），**量化覆盖率与偏差**；规模上到数百量级。
- **E3.2 大规模扫描**：**自建测试床**跑全样本；报各漏洞类别流行度、严重度分布、受影响规模估计。
- **E3.3 人工验证子样本**：随机抽样**人工核实 TP/FP**，并做**"真漏洞 vs 本职功能(dangerous-by-design)"判定**（需先定可辩护的判定标准）。

### RQ4 攻击者能干什么 —— 危害闭环
- **E4 深度案例**：代表性确认漏洞的**完整链路演示**（MCP 端点→tool 调用→容器内 root RCE→窃取网关凭据→横向打同容器其它 MCP）；明确攻击者模型并**用真实部署证据论证前提现实**。

### RQ5（加分）为什么会有这些漏洞 —— 根因刻画
- **E5 根因分类**：漏洞根因归类（输入直进 shell/路径处理/SSRF…），与服务特征（框架/是否 LLM 生成/流行度）关联。加 systematization-lite 厚度，强化 why-now。

## 3. 贯穿所有实验的刚性要求（审稿人常用驳回点）

1. **工具非确定性**：mcpfuzz 是 LLM 驱动、同目标多次跑会抖 → **每目标多轮跑 + 报检测率方差**，固定/记录 temperature 与种子。单跑一次＝轶事。
2. **统计口径**：概率性结果（攻击成功率/检测率）一律 **n 次 + 离散度**。
3. **冻结被测世界（可复现）**：每个 MCP **pin 版本/包/构建**，每次运行落 `env.lock`（容器摘要/依赖/内核），记**快照日期**；**聚合前归档原始输出**；写 `regenerate_figures.sh`。
4. **ethics＝测量合法性**：**自建测试床、不打第三方线上系统**（设计优势，明写）；真漏洞**负责任披露 + 时间线**；无人类受试者（说明不需 IRB）；暂扣的 live exploit 说清"为什么扣、何时放"。

## 4. 开跑前必须先搭好的"前置件"

1. **Ground-truth 标注基准集**（E1 地基）——CVE 数据集转为可跑的"有漏洞/干净"标注集。
2. **总体与抽样定义**（E3 合法性）——选定市场、统计 N、写死纳入标准。
3. **baseline 选型 + prior-art 调研**（E2）——查清有哪些现成可比工具。
4. **"漏洞 vs 本职功能"判定标准**（E3.3 / 全局可信度）——成文、可辩护的规则。
5. **可复现测试床**——版本 pin、env.lock、原始输出归档、多轮运行协议。
