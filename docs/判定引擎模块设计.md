# 判定引擎模块设计（草案）

> 本文件把 `docs/判定方法论.md` 再往下落一层：描述判定模块（方案架构中的「模块 6 判定采集」）内部**由哪些部件组成、部件间怎么接、数据怎么流**。纯架构设计，不含实现代码，不改现有代码。后续做别处发现需要调整时再微调。
>
> 定位回顾（分层）：方法论=做事原则；本文件=部件图与接线图；代码实现=更后面、需明确同意、且按基线版计划在对比后再动。

## 1. 模块边界：判定引擎负责什么、不负责什么

**负责（本模块内）**：在「发射台已就绪」的前提下，对一个待测参数执行全量判定套件、收集多通道证据、聚合并裁决出五态结论 + 证据包。

**不负责（上游/旁路提供）**：
- 连接与调用（驱动层）；
- sink 先验的产生（sink 推断）——本模块只**消费**先验，且先验只用于排序/预算，不作闸门；
- 发射台搭建（编排器）——失败则参数判为 UNREACHED/SKIPPED，不进入判定；
- 载荷字面量的具体合成（载荷合成）——本模块定义**探针契约**，由载荷合成填充。

### 上游输入
- 持久会话 session + 发射台给出的合法基线实参 base_args；
- 目标工具 target、目标参数 param、param 的 **sink 先验（带排序/置信，不闸门）**；
- 该参数适用的**探针集合**（按漏洞类的「技术 × 语境 × 目标变体」并集，由载荷合成按探针契约产出）。

### 下游输出
- 该参数的 **Finding**：五态判决 + 证据包（命中通道、载荷、对照、观测差异、可复现序列）。

## 2. 核心接口对象（数据契约，概念层）

- **Probe（探针）** = `(载荷值, 良性对照值, 漏洞类, 适用观测底座, 预期可观测效应, 命中判据, 唯一token/canary)`。
  探针是**载荷合成与判定之间的接口对象**：合成负责造出载荷值与对照值，判定负责发射、观测、比对、裁决。
- **ChannelHit（通道命中）** = `(所属探针, 命中通道, 证据等级∈{铁证,可证,弱证}, 证据正文, 是否可复现)`。所有观测器/比较器统一产出此对象。
- **ReachSignal（触达信号）** = `reached ∈ {yes, no, unknown}` + 依据。用于区分「疑似无」与「未触达」。
- **Finding（在现有基础上扩展）**：新增 `verdict ∈ 五态`、`evidence_bundle`（多通道证据列表）、`control`（对照信息）、`sequence`（复现序列）。

## 3. 内部部件（六个）

### 3.1 探针调度器（Probe Scheduler）
- 遍历探针集合，按通道编排发射；在 base_args 之上替换目标参数值逐条调用。
- 管理**执行策略**：默认全量发射、不因未命中提前停；仅在该参数已 CONFIRMED 后早停（研究模式可配置继续收齐证据）；按 sink 先验对探针集合排序、分配预算。
- 持有预算配置：`max_payloads` 放大、`delay`、时序重复次数 `K`、带外 poll 轮次/间隔、总请求上限。
- 每次调用把「真正发出的嵌套实参 + 响应 + 报错 + 漏洞类/通道」全量落盘（沿用现有 payload.sent 全量日志）。

### 3.2 通道观测器集（Channel Observers，五个观测底座各一）
统一产出 ChannelHit。
- **带内观测器（被动，每次调用都看）**：在 response + error 文本里跑 canary 精确匹配、真实文件内容签名匹配、错误指纹、标记反射。
- **带外观测器**：维护 token↔probe 映射；套件发完后批量 poll 回连服务器，按 token 归并命中。
- **时序观测器**：度量响应时延，重复 `K` 次，统计阈值判定（抗抖动在此）。
- **跨工具观测器**：在目标服务存在**配套读/写工具**时追加；用另一工具读回 canary（命令注入写文件、参数注入选项写文件、路径穿越写穿越、SQL 写行等共用）。
- **存活观测器**：整套套件打完后轻量 ping；无响应→崩溃/DoS 的 ChannelHit。

### 3.3 差分比较器（Differential Comparator）
- 对配了良性对照的探针，比较「活性 vs 对照」的观测（内容/行为/时延/结果集），只认**稳定、可重复的分化**。
- 时序差分、布尔差分的重复与阈值判定在此完成。
- 产出带证据等级的 ChannelHit（差分成立通常记「可证」，个别如求值差分回现记「铁证」）。
- **差分为骨架**：SSRF 的信任边界差分、路径穿越的越界/深度差分、参数注入的接受/拒绝差分都经此，天然排除「本职功能」误报。

### 3.4 触达判定器（Reachability Judge）
- 产出 ReachSignal，用于支撑「疑似无 vs 未触达」的区分。
- 依据：对照/基线调用是否成功；报错性质是「前置参数校验拒绝」还是「业务逻辑/后端处理」；带内是否出现「参数已被后端处理」的迹象（值被回显、出现后端程序输出等）。
- `reached=yes` 且全套无命中 → 疑似无；`reached=no` → 未触达（我方失败，单列、触发重试/换策略）；`unknown` → 保守按未触达并重试。
- **标注为难点**：黑盒下「是否真的触达 sink」本身不易判，是本模块需持续细化的部分。

### 3.5 证据聚合器（Evidence Aggregator）
- 汇集该参数判定会话内所有 ChannelHit；去重、按证据等级排序；多通道独立命中→置信叠加。
- 组装 evidence_bundle：每个命中附通道、载荷、对照、观测差异/命中正文、可复现序列。

### 3.6 五态裁决器（Verdict Resolver）
- 依据聚合结果 + ReachSignal → 映射五态：
  - **确认有 CONFIRMED**：任一「铁证」，或「可证」经重复确认；
  - **疑似有 SUSPECTED**：仅「弱证」、无硬证佐证 → 待人工复核；
  - **疑似无 LIKELY_CLEAN**：`reached=yes` 且全套无命中；
  - **未触达 UNREACHED**：`reached=no`；
  - **未测成 SKIPPED**：发射台/连接失败（在进入本模块前即判定）。
- 弱证只给「疑似有」、绝不进「确认」——保护确认数可信度。

## 4. 数据流（端到端）

```
发射台就绪(session, base_args)
      │
      ▼
探针调度器 ── 取探针集合(按sink先验排序) ──► 逐探针发射(替换目标参数)
      │                                            │
      │                         ┌──────────────────┼───────────────┐
      │                         ▼                  ▼               ▼
      │                   带内观测器(每次)   收集带外pending   时序重复度量
      │                         │                  │               │
      ▼                         │                  │               │
配对探针 ──► 差分比较器 ◄────────┘                  │               │
      │          │                                 ▼               │
      │          │                          带外批量poll           │
跨工具/存活观测(时机到) ─────────────► 全部 ChannelHit ◄────────────┘
                                             │
                                             ▼
                                   证据聚合器(去重/排序/叠加)
                                             │        ▲
                                             ▼        │ ReachSignal
                                      五态裁决器 ◄── 触达判定器
                                             │
                                             ▼
                                   Finding(五态 + 证据包) ──► 事件/落盘
```

## 5. 与其它模块的接口

- **sink 推断 → 判定**：提供 param 的 sink 先验（排序/置信）。先验**只影响探针集合的排序与预算分配**，不决定「发不发」——凡该参数够得到的漏洞类套件都发（呼应「让判定裁决、不闸门」）。
- **载荷合成 → 判定**：按 Probe 契约产出探针（载荷值 + 对照值 + 预期效应 + 命中判据 + token/canary）。判定定义契约，合成负责填充。
- **编排器 → 判定**：保证发射台就绪并给出 base_args；发射台失败不进入判定。
- **驱动层 ← 判定**：判定通过驱动层在持久会话上发起每次调用。

## 6. 成本张力与折中（需正视）

「全类 × 全量变体」会使请求数膨胀。约束手段：
- sink 先验**排序**：高先验漏洞类的探针先发、变体给更多预算；低先验仍会发但预算收敛。
- **预算上限 + CONFIRMED 早停**：覆盖优先，但有总闸。
- 被动通道（带内/错误指纹）零额外请求，优先吃满。
- 可配的「研究模式（收齐全部证据）」与「常规模式（命中即止）」两档。

## 7. 待细化难点（留待后续微调）

- **触达判定（3.4）**：黑盒下判「是否真的到达 sink」不易，直接决定「疑似无/未触达」的准确性。
- **跨工具配对的自动发现**：如何从工具目录里识别出可配套的读/写工具对。
- **时序阈值标定**：K 次重复与阈值如何对不同网络条件自适应。
- **全类全量的预算策略**：排序与预算的具体分配函数。

## 8. 与现有代码的对应（仅说明演进方向，不现在改）

- 现有 `oracle.observe_response` / `oracle.poll` ≈ 带内观测器 / 带外观测器的雏形；
- 现有 `executor._attack_param` ≈ 探针调度器 + 简化聚合的雏形（当前只有带外/反射两通道、四态）；
- 现有 `Finding` 需扩展为五态 + evidence_bundle；
- 差分比较器、触达判定器、跨工具/时序/存活观测器、疑似有状态均为**新增**。
- 演进遵循 baseline 版计划：方案级改动待基线对比后再落代码。
